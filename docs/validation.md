## Verified in v0.3.12

0.3.12 paints every composition surface but the acrylic noise tile in a bitmap of its own and copies it into the atlas (`PaintLocal`, `src/surface_paint.h`), so the stills no longer move when surfaces are added or removed. The noise tile, a CPU bitmap copied whole-pixel into its own surface (`NoiseBrush`), never depended on the atlas position.

| Area | Evidence and scope |
| --- | --- |
| Cause | `Paint` drew each surface it painted in place in the composition atlas, with the atlas offset as a single-precision DIP translation (offset × 96 / DPI). Pixel snapping (`Snap` in `src/artwork.cpp`) and DirectWrite's glyph positions saw that translation's rounding error, so a mark or name exactly half a device pixel off the grid could round either way, and the result changed with the atlas layout: between 0.3.10 and 0.3.11 the removed gate surfaces moved several tiles and names by one pixel. Now `draw` sees its own surface at the origin with no transform, and the finished bitmap is copied pixel for pixel. |
| Atlas independence | `iconography_tests` (227 checks) draws GitHub's mark, the generic glyph and a name, stepped in eighths of a device pixel, at 154 and 77 DPI (a 0.8 reel at 200% and 100%) and at eight atlas offsets up to 4093 px: through `PaintLocal` every offset gives the pixels of the origin; drawn in place as before, 14 of the 16 differ. |
| Interaction | `tests/run-reel-seam.py` passed all 13 groups. |
| Rendering against 0.3.11 | `output/runtime/v0.3.12`: 94 of 105 stills differ from v0.3.11, all at half-pixel ties that now resolve one way. Marks of odd size in even tiles move by one pixel inside an unchanged tile (for example Gemini at 100% and 150%); names and the EN and 100% monograms keep their baseline and change only the anti-aliasing of their top row. Names and marks stay within half a pixel of their centers, as before. ## Tray icon kept across updates (fork contribution, 2026-10-25)

Recorded on the same ARM64 PC, on top of the monochrome tray icon above. Windows keeps a tray icon's "show on the taskbar" choice in `HKCU\Control Panel\NotifyIconSettings`, one key per icon with its `ExecutablePath`, optional `IconGuid` and `IsPromoted`. A packaged reel runs from a folder named by its version, so every update was a new icon to Windows and went to the hidden overflow.

| Area | Evidence and scope |
| --- | --- |
| Cause | Each step updated the installed reel in place with `Add-AppxPackage -ForceApplicationShutdown`, the updater's own `AddPackageAsync` path, and listed the reel's keys. Identified by `hWnd` and `uID`, every version got a new key without `IsPromoted`: 0.3.8.0 to 0.3.8.1 with the plain executable, and 0.3.8.2 to 0.3.8.3 with `CopilotReel.exe` itself Authenticode-signed with the development certificate. A full uninstall and install behaves the same. |
| Fix | The icon is identified by a fixed GUID (`kTrayGuid`, `NIF_GUID` in every `Shell_NotifyIcon` call through `TrayData`). From 0.3.8.4 to 0.3.8.5 (signed executables), 0.3.8.5 to 0.3.8.6 (signed to unsigned) and 0.3.8.6 to 0.3.8.7 (both unsigned), Windows kept the one key and only moved its `ExecutablePath`, so the Authenticode exception in the `NOTIFYICONDATA` documentation is not needed for a package update here. The user then showed the icon at 0.3.8.7 (`IsPromoted=1`); after an uninstall and install of 0.3.8.0 the same key read `IsPromoted=1` and the icon was on the taskbar. |
| Fallback | Should Windows refuse the GUID (the documentation's case of an unsigned binary moved after registering it), `AddTray` removes a stale icon, tries once more, and then adds the icon by `hWnd` and `uID` as before, logging it, so the icon always shows. Diagnostics report `trayIconGuid`. This path was not reached on this machine. |

The keys of the earlier versions stay in the registry as Windows leaves them for every app; they no longer match any installed executable. Not verified: x64, and an update through the in-app updater itself (it uses the same package-manager call).

## Remaining checks and known limits

- Real physical Copilot short-tap/hold/release delivery, including hidden-window discovery and pathological Shell scheduling. Automated commands and messages do not establish hardware timing.
- Presentation/resource measurements at 60/144/240 Hz, mixed refresh rates, battery/energy saver, and a longer idle baseline. Compositor animation alone does not guarantee smoothness on every GPU.
- Live frosted-backdrop appearance over real content (this machine has Windows transparency effects off), real high-contrast themes, reduced motion, device loss, mixed-DPI multi-monitor transitions, and small-work-area usability.
- Known limits in 0.3.4: during the 83-133 ms exit a click over the plate is ignored but not passed to the application beneath (`HTTRANSPARENT` forwards only within the thread); retargeting the seat twice within one spring settle measures the shortest arc from the previous target, so a 180-degree flick can swing the long way round.
- Cold, running, and minimized instances of every preset application. Discovery is verified on this machine for ChatGPT/Codex, Claude, ZCode, and VS Code; the remaining presets ask for their actual installed target.
- Comprehensive accessibility/UI Automation semantics for custom radial controls. The focused text editor uses native controls.
- ARM64 runtime. The 2026-10-20 package is a native ARM64 image checked by its PE header and by this x64 host refusing to start it. Behavior, appearance, and Copilot-key registration on ARM64 hardware are still open.

## Repeatable checks

```powershell
.\tools\build-capture-tool.ps1
.\tools\test.ps1
.\tools\test.ps1 -Tier installed
.\tools\verify-registration.ps1
```

`tools/test.ps1` is the one entry point for unit, smoke and regression tests; the [testing plan](testing-plan.md) lists its tiers. The default regression tier checks that the eight version copies agree, builds Release x64 with every unit test, runs every group of `tests/run-reel-seam.py` and compares the stills of `tools/capture-seam.py` with `output/runtime/v0.3.13`; `-Tier smoke` does the same version check, build and unit tests, then runs only the seam preflight and groups `a` and `hub`, without the still comparison, and `-Tier installed` builds nothing and checks that the installed package's executable equals `build\Release\CopilotReel.exe` and is running. Each run writes every step's log and a `summary.json` under `artifacts/qa/test-<stamp>/` and exits 1 when a step fails. The seam runners start separate unpackaged test instances with their own data directories and drive them through the test seam: they never move the pointer, send input or take the foreground, and the installed reel keeps running. `tools/verify-registration.ps1` checks the installed package's Copilot key provider and state declarations and reports whether the user's key selection names it.

`tests/run-radial.py`, `tests/run-language-invariance.py` and `tools/capture-v034.py` are 0.3.4 evidence, and `tools/capture-native-wheels.py` is older; they assume the five-item hub with Preferred agent and the 384 DIP window. They drive the real pointer and need the installed reel to quit first, so they run only while nobody uses the desktop, and `tools/open-installed.ps1 -View Background` restarts the installed reel afterwards. Historical v0.2 tests are archived in `tests/legacy-v0.2/`; they do not describe current UI acceptance.

`tools/install-development.ps1 -PackagePath <signed-msix>` validates signature, identity, and tested executable before removing the exact old package. It shuts down safely, backs up configuration, performs uninstall/install, restores verified data, and checks installed binaries/assets. It does not import certificates or change the Copilot target.

`tools/build-capture-tool.ps1` builds a standalone Windows Graphics Capture helper (`build\Release\capture-window.exe`), which the still comparison and `tools/record-demos.py` need; `tools/build.ps1` does not build it. It captures only the application window it is given, even when another desktop window overlaps it, so the stills are actual native renders, not PDF design scenes. Desktop screen captures were rejected when occlusion produced blank images.
