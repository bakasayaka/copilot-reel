# Agent rules

Copilot Reel is developed by several coding agents in turn. Before starting, read this file, `git log` and `git status`. The documents in `docs/` remain the product and design contract; this file holds the rules every agent follows.

The handoff log is not part of the repository (the user's decision, 2026-10-25): each machine keeps it in `AGENTS.local.md`, which `.gitignore` excludes. It records the sessions and what each changed, the current state, the open product questions and the machine's own configuration. Read it when it exists, add your session to it before handing over, and never commit it or copy its content into commit messages, pull requests or public docs.

## Rules for every agent

- Development artifacts are English: code, comments, script output, docs, design tokens, VI and commit messages. Replies to the user are in Chinese.
- The product UI defaults to English, with Simplified Chinese (`ZH`) and Japanese (`JA`, added 2026-10-25) as options. All languages share one profile: switching language never changes apps, order, icons or the preferred agent. Every `Tr` call carries all three strings.
- Japanese wording follows Microsoft's Japanese Windows terms and uses kanji where a natural kanji word exists, fewer katakana loanwords (the user's request, 2026-10-25): 簡易メニュー, 既定, 最新版, 大きさ, 個人用設定, 問題 rather than エラー. System nouns that Windows writes in katakana stay katakana (アプリ, インストール, テーマ, ダーク モード), with Microsoft's half-width space between katakana words.
- Unit, smoke and regression tests run through `tools/test.ps1` (`-Tier unit|smoke|regression|installed`, `-Installed`), never as steps run one by one by hand (the user's rule since 2026-10-25). Add a new check to the script or to a runner it calls, and report its `summary.json`.
- README GIFs and stills come from `tools/record-demos.py` (the seam, a demo profile, logged launches) and `tools/readme-art.py`; each README language shows recordings made in that language (the user's rule since 2026-10-25). Never capture the desktop, the taskbar or personal apps for them.
- After every push to GitHub, release or not, reinstall Copilot Reel on the maintainer's machine from the pushed commit (the user's rule since 2026-10-23; a contributor's machine follows its own setup): build Release x64, package it, sign it with `signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /f artifacts\signing\CopilotReel-Development.pfx <msix>`, then `tools/install-development.ps1 -PackagePath <signed msix>`, which backs up the configuration, uninstalls the old package, installs the new one and restores the configuration. Then start it with `tools/open-installed.ps1 -View Background` and check that the installed executable's SHA-256 equals `build\Release\CopilotReel.exe` with `tools/test.ps1 -Tier installed`, which builds nothing. Skip the reinstall only when that check already passes. Release builds are reproducible (`/Brepro`, since 2026-10-25), so rebuilding the same tree keeps the hash.
- Only the newest version is kept (the user's rule since 2026-10-22): after a release is published, delete the older GitHub releases together with their tags (`gh release delete <tag> --cleanup-tag`, then `git tag -d <tag>`), and remove the older packages and release notes from `artifacts/`. The commits stay in history; configuration backups in `artifacts/backups/` are kept.
- Every release carries the public certificate `artifacts\signing\CopilotReel-Development.cer` next to the packages, and its notes carry the install steps from `v0.3.6.1-beta` (thumbprint check, import into `LocalMachine\TrustedPeople`, removal). Never upload the PFX. Every package signature is timestamped.
- Every release is a full release marked Latest, never a prerelease (the user's rule since 2026-10-25): GitHub shows only the Latest release in the repository's Releases sidebar and never makes a prerelease Latest, so a prerelease leaves the sidebar showing a tag count. Create it with `gh release create ... --latest` and no `--prerelease`, and do not call it unstable in its notes. The updater reads prereleases too, so this changes nothing for installed reels.
- Commits use the existing author, `baka_sayaka <60833924+bakasayaka@users.noreply.github.com>`, passed per command. Never change git config. Commit or push only when the user asks.
- Interaction and visual checks run through the test seam: `tests/run-reel-seam.py` and `tools/capture-seam.py` drive a separate unpackaged test instance through its own channel. They never move the pointer, send input or take the foreground, and the installed reel keeps running.
- `tests/run-radial.py`, `tests/run-language-invariance.py` and `tools/capture-v034.py` are 0.3.4 evidence, and `tools/capture-native-wheels.py` is older evidence; all of them assume the five-item hub with Preferred agent and the 384 DIP window size. They drive the real pointer, need the installed instance to quit first and must not run while the user works. Restart the installed reel afterwards with `tools/open-installed.ps1 -View Background`.
- Settled decisions; do not reopen them without the user:
  - Soft Orbit with one plate.
  - A quiet center: one name on hover, no titles or captions.
  - EN/ZH/JA and sun/moon show state in the icon itself.
  - Japanese text uses the bundled Reel Sans JP, a renamed Noto Sans JP subset at 400 and 600, the open face closest to Hiragino Sans; Yu Gothic UI covers what the subset lacks and the GDI controls (requested 2026-10-25, `docs/visual-identity.md`, Typography).
  - The README follows direction A, Keynote: a centered hero GIF, three steps, quiet sections and pill language buttons, in English, Simplified Chinese and Japanese (chosen 2026-10-25); developer content lives in `docs/development.md`.
  - One merged `+` entry.
  - Official vendor artwork with one tile treatment.
  - The reel opens centered on the pointer and moves only as far as needed at screen edges. Wherever that move leaves the pointer, on the plate or outside it, it selects by direction as soon as it moves; there is no center entry (changed 2026-10-26; from 2026-10-22 a pointer left outside the plate entered the center first).
  - No line, perimeter-sweep or accent-stroke opening animation.
  - While the reel is closed, a short tap opens the preferred local agent, never a web page; a hold opens the reel.
  - Inside an open menu every input confirms, goes back or adjusts: a tap, or a new hold and its release, confirms the selected item (approved 2026-10-21).
  - The reel starts in the background at sign-in through a packaged startup task (approved 2026-10-21).
  - The reel draws at 0.8 of its DIP geometry (`geometry.scale`; requested 2026-10-23), times the user's Reel size step of 70%, 85%, 100% or 115%, default 100% (`geometry.sizeSteps`; accepted 2026-10-25). Text keeps a device-pixel floor while the geometry scales: the center name never below 10 px (the user's choice over the proposed 11, at which the 70% step trimmed Visual Studio Code), the monograms below 9 px, the update dot below a 3 px radius; text below 13 px uses Segoe UI Variable Small (`typography.minimumPx`; audit P1, approved 2026-10-25).
  - The hub has seven items: Language, Appearance, Reel size, Tray icon, Manage apps, Add app and About (Reel size accepted 2026-10-25 with PR #1, About requested the same day, Tray icon requested 2026-10-26). Tray icon switches the notification-area icon between color and monochrome, as the tray menu's Monochrome icon does, and shows the choice in its icon: the reel's color mark or the mark alone.
  - About is a radial page (art option C, chosen 2026-10-25 from three drawn with the VI generator): the reel's own mark named by its version, GitHub's official Invertocat (black or white) named `baka_sayaka` and opening the repository (split 2026-10-26 from one `<version> · baka_sayaka` name, which trimmed at the 70% step), Auto-check and Auto-install switches that show their state in the icon (filled switch on, outlined off, never accent), and the update tile. Every center name fits the 160 DIP line (132 before audit P1).
  - Updates are pulled from the GitHub releases, never pushed: checking is on and installing off by default; a waiting update shows only a small accent dot on the hub's About tile and on the update tile, no notification. Windows installs it and restarts the reel; only packages signed by a thumbprint in `kTrustedSigners` (`src/updates.h`) are installed, so a replacement certificate goes into that list one release before it signs.
  - Apps are reordered only by dragging their tiles on Manage apps; while a tile is dragged the center shows a red trash, and dropping on it takes the app out of the reel without deleting it: its settings wait first on Add. App actions has no reorder chevrons (requested 2026-10-23).
  - The preferred agent is set only from an app's actions page; the hub has no Preferred agent entry (requested 2026-10-23).
